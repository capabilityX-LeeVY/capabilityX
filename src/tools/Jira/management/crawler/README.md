# Bug Analysis and Statistics Tools User Guide

## Overview

This toolset includes three main functionalities:
1. **Jira Bug Crawler** - Crawl bug data from Jira
2. **Bug Data Analysis** - Analyze bug accessibility classifications using GPT
3. **Statistics Report Generation** - Generate statistics and summary of analysis results

---

## 1. Jira Bug Crawler Tool

### Features
- Supports multiple query methods: JQL, recent bugs, custom filters, specific IDs, etc.
- Supports two output modes: **Store to Database** or **Export to Excel**

### Usage

#### Basic Usage

```bash
# Crawl bugs from the last 7 days and store to database
python3 src/run_jira_crawler.py recent --project SPARK --days 7

# Crawl bugs from the last 7 days and export to Excel
python3 src/run_jira_crawler.py --output excel recent --project SPARK --days 7
```

#### Using JQL Query

```bash
# Use JQL query and export to Excel (with default filename)
python3 src/run_jira_crawler.py --output excel jql --jql "project = SPARK AND status = Open"

# Use JQL file and specify output filename
python3 src/run_jira_crawler.py --output excel --output-file my_bugs.xlsx jql --jql-file dev.jql
```

#### Crawl by ID

```bash
# Crawl specific bugs by ID and export to Excel
python3 src/run_jira_crawler.py --output excel ids --ids "SPARK-12345,SPARK-67890"

# Read ID list from file
python3 src/run_jira_crawler.py --output excel ids --ids-file bug_ids.txt
```

### Parameter Description

**Global Parameters** (must be placed before subcommands):
- \`--output {db,excel}\` or \`-o\` - Output mode (default: db)
  - \`db\`: Store to MySQL database
  - \`excel\`: Export to Excel file
- \`--output-file FILE\` or \`-of\` - Specify Excel output file path (optional, auto-generated by default)
- \`--database NAME\` or \`-d\` - Database name (default: jira_crawler_db)

**Subcommands**:
- \`recent\` - Crawl recent bugs
- \`jql\` - Use JQL query
- \`ids\` - Crawl by Jira ID
- \`custom\` - Custom filter conditions
- \`projects\` - Crawl multiple projects
- \`stats\` - View database statistics

## 2. Bug Data Analysis Tool

### Features
- Read bug data from Excel file
- Call GPT API for accessibility classification analysis
- Output new Excel file with classification results

### Usage

```bash
# Use default configuration
python3 src/core/processor/dev_bug_processor.py

# Or use in Python code
from core.processor.dev_bug_processor import BugProcessor

processor = BugProcessor(
    input_file='dev_bugs.xlsx',
    output_file='data_with_response.xlsx',
    template_file='src/prompts/bug_analysis_template.md'
)
processor.process()
```

### Output Columns

The analyzed Excel file will contain the following new columns:
- \`Meeting_Module\` - Meeting module
- \`Accessibility_Category\` - Main accessibility category
- \`Accessibility_Subcategory\` - Accessibility subcategory
- \`WCAG_Standard\` - Related WCAG standard
- \`Complete_Analysis\` - Complete analysis result (JSON format)

## 3. Statistics Report Generation Tool

### Features
- Count bug quantities and percentages by category and subcategory
- Generate reports in Excel and Markdown formats
- Display status for each category (✅ has bugs / ❌ no bugs)

### Usage

#### Generate Excel Statistics Report

```bash
# Analyze default file
python3 src/core/processor/bug_statistics.py

# Analyze specified file
python3 src/core/processor/bug_statistics.py --input data_with_response.xlsx --output statistics.xlsx
```

#### Generate Markdown Report

```bash
python3 src/core/processor/generate_md_report.py --input data_statistics_report.xlsx --output report.md
```

### Output Content

Statistics report includes:
1. **Overall Statistics** - Total bug count, category count
2. **Detailed Statistics Table** - Count, percentage, and status for each module and sub-item
3. **Module Summary** - Statistics grouped by module

## Complete Workflow Example

### Scenario: Crawl bugs from Jira → Analyze classification → Generate statistics report

```bash
# Step 1: Crawl bugs from Jira and export to Excel
python3 src/run_jira_crawler.py --output excel --output-file dev_bugs.xlsx jql --jql-file dev.jql

# Step 2: Analyze bugs and add accessibility classification
# First modify the input_file path in dev_bug_processor.py to 'dev_bugs.xlsx'
python3 src/core/processor/dev_bug_processor.py

# Step 3: Generate statistics report
python3 src/core/processor/bug_statistics.py --input data_with_response.xlsx --output bug_statistics.xlsx

# Step 4: Generate Markdown format report
python3 src/core/processor/generate_md_report.py --input bug_statistics.xlsx --output bug_report.md
```

## Important Notes

1. **Parameter Order is Important**
   - Global parameters (\`--output\`, \`--output-file\`) must be placed before subcommands
   - ✅ Correct: \`python3 src/run_jira_crawler.py --output excel jql --jql-file dev.jql\`
   - ❌ Wrong: \`python3 src/run_jira_crawler.py jql --jql-file dev.jql --output excel\`

2. **Dependencies**
   - Ensure installed: \`pandas\`, \`openpyxl\`, \`jira\`, \`openai\`
   - Installation command: \`pip install -r requirements.txt\`

3. **Configuration**
   - Jira API token needs to be configured in \`config/api_key.json\`
   - OpenAI API key needs to be set in environment variables or config file

4. **Excel File Format**
   - Analysis tool expects first 3 columns in Excel file to contain: Jira ID, Summary, Description
   - Statistics tool requires \`Accessibility_Category\` and \`Accessibility_Subcategory\` columns

## FAQ

### Q: Why are command line arguments not recognized?
A: Ensure global parameters (like \`--output\`) are placed **before** subcommands (like \`jql\`).

### Q: How to customize output filename?
A: Use the \`--output-file\` parameter:
```bash
python3 src/run_jira_crawler.py --output excel --output-file my_custom_name.xlsx jql --jql-file dev.jql
```

### Q: Why does "JSON Error" category appear in statistics report?
A: This indicates that some bugs' GPT analysis responses cannot be correctly parsed as JSON format. Check the analysis template or reprocess these bugs.

### Q: How to only count bugs of specific categories?
A: You can filter specific categories in Excel first, then save as a new file before generating statistics.
